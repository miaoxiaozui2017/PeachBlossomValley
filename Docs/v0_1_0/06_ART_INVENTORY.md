> 用途：美术重绘的交付清单 + 两界拆场景的资源归属表。
> 数据来源：`Assets/Art/Placeholder/` 实际文件、`Assets/Resources/Data/` 物品资产、`SceneBuilder.cs` / `ContentExpansion.cs` / `ShopWorldBootstrap.cs` 的生成逻辑。
> 盘点时间：v0.6.x 灰盒阶段。

## 0. 一句话结论

当前**没有一张正式美术**：113 张 32×32 程序生成的占位 PNG、38 个交互点全是 8×8 色块、全部 UI 是纯色矩形。

重绘要补的资源位共 **约 240 个**，其中最大头是 **111 个物品图标**（占 46%）和 **38 个建筑**。

## 2. 硬规范（必须照此交付，否则要改代码）

| 项 | 值 | 原因 |
|---|---|---|
| 画布尺寸 | **32 × 32 px** | 全项目统一，`SceneBuilder` 所有贴图都是 32×32 |
| Pixels Per Unit | **32** | 1 格 = 1 世界单位 = 32px；改 PPU 会让角色与碰撞体、地块对不齐 |
| 轴心 Pivot | **中心 (0.5, 0.5)** | 运行时 `Sprite.Create(..., new Vector2(0.5f,0.5f), 32f)` 全用中心轴心 |
| 过滤 Filter | **Point（无插值）** | 像素风；`TextureImporter.filterMode = Point` |
| Mipmap | **关闭** | 同上 |
| 格式 | PNG，RGBA32，透明底 | 现有占位即此格式 |
| 命名 | 见 §5 命名规则 | 代码按文件名/物品 id 找图 |

> **替换方式（重要）**：直接**覆盖同名 PNG** 即可换皮，`.meta` 里的 GUID 不变，场景和数据资产里的引用自动生效，**不用改代码、不用重建场景**。
> 注意 `SceneBuilder.GetSprite()` 有 `if (!File.Exists(path))` 判断，只补不改，所以覆盖是安全的。

## 7. 需要你确认的 3 个美术决策

1. **角色是否要行走动画？**
   现在没有 Animator，`PlayerController` 已预留 4 向参数。要动画 = 每个角色 4 向 × 3-4 帧 = 约 12-16 张/角色（9 NPC 就是 100+ 张）；不要动画 = 每个角色 1 张，体积小很多。

2. **建筑要不要放大到 2×2 格？**
   1 格（32×32）出图零代码改动；2 格（64×64）更好看，但要改 `BoxCollider2D` 尺寸和 `StationLayout` 间距。

3. **两个世界的美术基调？**
   桃花谷＝暖色水墨/田园；现代＝冷色扁平/霓虹？这决定现代那 5 个资源位和 UI 冷色皮肤怎么定。

## 8. 双场景拆分（已实施：叠加式）

**做法**：现代世界做成独立场景 `Assets/Scenes/02_Modern.unity`，运行时**叠加加载**，桃花谷场景**永不卸载**。

```
01_FarmGreyBox.unity   ← 常驻：系统 + 农田 + 10 工坊 + 9 NPC + 牲畜 + 储物箱 + 出货箱
02_Modern.unity        ← 叠加：地面 + 现代杂货铺 + 古玩店（美术可单独在此场景工作）
```

**为什么不用「卸载式」切换**：卸载会销毁 `Systems`（38 个组件）与 27 个运行时补建对象，背包/钱包/任务/好感/牲畜/储物箱状态全部需要迁移，且 58 个单例要逐个补防重。叠加式零状态迁移。

**生成方式**（必须由你在 Unity 里执行，我这边无法运行 Unity）：

```
菜单栏 → PBV → 生成现代场景 (02_Modern)
```

会做三件事：生成 `tex_modern_ground.png` / `spr_shop_modern.png` / `spr_shop_antique.png`、建好场景并保存、把 `01_FarmGreyBox` 与 `02_Modern` 一起写进 Build Settings。

**没生成也不会坏**：运行时检测不到 `02_Modern` 就自动退回「程序补建现代店」的旧逻辑，游戏照常能玩。

**美术怎么用这个场景**：
- 现代场景里只有 3 个物体：`ModernGround`（48×26 纯色地面）、`ModernShop`（16,9）、`AntiqueShop`（20,9）
- 直接把占位 Sprite 换成正式图即可，位置不用动（`StationLayout` 会按坐标对齐）
- 谷内场景随便改，两边互不影响

**两界资源归属**见 §4。结论：现代只需 **5 个独有资源位**（地面 1 + 店铺 2 + 传送门 1 + 街道装饰 1），其余全部复用桃花谷。
