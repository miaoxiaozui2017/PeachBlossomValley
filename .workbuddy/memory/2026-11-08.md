## 23:55 修复「开局背包空，升级后才刷出物品」
根因：InventoryUI.Awake() 里 `if (InventorySystem.Instance != null) OnInventoryChanged += RefreshAll`
  订阅时 Instance 可能还是 null（同物体组件 Awake 顺序不保证，当前场景又被 Unity 重写过），
  订阅静默丢失且之后再没补。初始物资由 `StarterKit.Update()` 在**首帧 Update** 才发放，
  晚于所有 Start，所以物品已进背包但 UI 收不到通知；升级扩容时 ExpandCapacity 触发了一次
  刷新（或被容量轮询兜到），物品才出现 —— 完全对应用户描述。
修法（InventoryUI，三重兜底）：
1) 订阅从 Awake 移到 Start 的 `EnsureSubscribed()`，并在 Update 开头懒补订阅（_subscribed 标志，只补一次）；
2) 把「懒订阅 / 容量变化 / 每 0.2s 定时 RefreshAll」放到 `keyboard == null` 的提前 return **之前**；
3) `TogglePanel()` 打开瞬间强制 `RefreshAll()`。
另：OnDestroy 改用 _subscribed 判断退订。
验证：dotnet build 运行时程序集 0 错误；试玩指南加验收项 113（开局立刻按 Tab 就能看到初始物资）。
经验：本项目凡是「同物体上单例 + 事件订阅」一律不要在 Awake 订阅，统一 Start + 懒订阅 + 轮询兜底
  （此前 QuestLogUI 已踩过同一个坑）。
