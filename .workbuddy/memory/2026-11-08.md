
## 上午 UI 交互重大 bug 修复（用户报：提示遮挡 + 造纸台按钮点不动）
根因1（按钮完全点不动）：场景里从未创建 EventSystem（SceneBuilder 没有，场景文件 grep=0）。
  → 所有 uGUI Button 收不到点击。修：新建 UI/UIEventSystemBootstrap.cs，
    HUD.Awake 与 InteractionPromptUI.Awake 调 Ensure()，运行时自动补 EventSystem+StandaloneInputModule。
    activeInputHandler=2(Both)，旧输入可用。幂等，无需重建场景。
根因2（遮挡+吃点击）：7 个面板(HelpUI/BuildUI/CraftingUI/CookingUI/MineUI/ShopUI/ToolUpgradeUI)
  的全屏半透明 BG 挂在 canvasGo 下，不受 _root.SetActive 控制 → 常驻叠加在最上层、
  raycastTarget=true 吃掉所有点击。修：加 _canvasGo 字段，BuildUI 赋值，
  所有 _root.SetActive → _canvasGo.SetActive（整块 Canvas 一起开关）。
  同时 QuestLogUI/SkillPanelUI 统一改。
根因3（视觉层级）：HUD sortingOrder 40、交互提示 55、背包 50 都高于功能面板 23~30。
  修：HUD→5 且移除 GraphicRaycaster、所有 Text/Image 关 raycastTarget；
  交互提示→10 同理；背包→15 且 hotbar 底板关 raycastTarget；
  HUD 底部操作条移到左下角，避开中央 [E] 交互提示。
根因4（材料够但按钮灰）：CraftingSystem/CookingSystem/FishingSystem/MineSystem/ToolManager
  用 Resources.FindObjectsOfTypeAll<ItemData>() 只返回已加载对象 → 材料资产引用为 null
  → CanCraft 恒 false。修：全部改 Resources.LoadAll<ItemData>("Data")；
  CraftingSystem 解析失败不锁 _resolved；CraftingUI.Refresh 主动重试解析。
兼容：Ensure() 里禁用并销毁旧场景残留的 IntroSystem（全屏黑底）、
  自动补挂 HelpUI 组件 → 不重建场景也能用 H 帮助页。
验证：Unity 编辑器开着，原项目 batchmode 因「Multiple Unity instances」崩溃；
  改用 _CompileCheck 项目副本（只复制 Scripts/Editor/ProjectSettings/Packages）编译验证。
  ⚠️ 提交前必须删除 _CompileCheck（避免把 Library 缓存提交进 git）。
文档：Docs/v0_1_0/04_PLAYTEST_GUIDE.md 加 80~84 共 5 条 UI 验收项。
